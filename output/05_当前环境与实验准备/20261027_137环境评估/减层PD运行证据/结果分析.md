# N16单机PD：原异步ON与分段候选ON自然冷/热结果

原始证据仅保留本机/容器，仓库以本页精简JSON为数值凭据。

两组各1冷＋2热，共6次均HTTP/benchmark成功，输入29696 token、输出300 token、0失败。第二热的客户端TTFT为原组0.548350s、候选0.532426s，相差15.925ms；**没有分段优化收益的因果证据**。候选两次自然热请求均后段先就绪，下一次调度时已收到全局完成，回到原路径，未发生分段admission或提前计算。六次输出全文两两不同，token级一致性与KV内容正确性为**NOT_VERIFIED**。

## 对照范围

本轮是减层单机PD机制诊断：P为N16、TP4/PP2、分层8/8、DSA CP、正常Mooncake＋LMCache producer；D为DP2/TP4/PP1。两组保留MTP3、原78层draft权重路径、相同客户原文、N1/C1及原输出300。共同私有draft配置修复保持78层构造及GLM量化家族；P使用FUSED_MC2=0、HCCL_BUFFSIZE=512。两份P记录的原生`vllm serve`参数相同，候选增加私有阶段模块/事件接线，正常producer的两个local-P标志均为false。

原组P PID1497574，候选P PID1505582；**D0/D1始终沿用同一进程，候选运行在原组三次之后**。各组cold指P侧LMCache未命中，不能解释为整个P/D/编译/设备环境同等冷态。N16 target与原78层MTP不是训练一致模型，不按文本语义评质量，也不与完整78层单机P或原1P1D正式性能结果混比。本表仅含自然请求；单独的`DIAGNOSTIC_ONLY`延通知功能实验不纳入本表。

P external来自LMCache，D0 external来自Mooncake P→D，不能都称LMCache命中。新算值同时由`request_prefill_kv_computed_tokens`与`prompt_tokens_by_source{source="local_compute"}`支持；四次热请求P external transfer均29695，D0六次均29696，local cache hit均不增加。本轮没有D0重算29696前缀的证据。原cold D0 prefill虽达8.866s，新算前缀仍为0，说明prefill墙钟不是重算token数的替代指标。

## 自然候选未触发分段派发

自然trace（`stage-candidate-trace/stage-1505817.jsonl`）共8行，对应两次热请求：

| 请求 | 首次promotion | 后段READY→前段READY的CPU观察间隔 | 下一promotion | stage admission |
|---|---|---:|---|---|
| 首次warm | front_not_ready / deferred | 29.194566ms | request_global_finished / deferred_to_original | 无 |
| 第二warm | front_not_ready / deferred | 32.311640ms | request_global_finished / deferred_to_original | 无 |

两次前段READY时`all_kv_ready=true`，下一promotion的`request_global_finished=true`，因此回原路径。无`stage_batch_admitted`、前后段execute提交、worker开始/设备完成、sample解析或core FIFO消费事件。时间戳是CPU事件观察时间，不能直接推DMA完成先后或设备耗时。

当前证明真实事件能进入核心登记与调度决策，不能称分段executor/worker新路径已在NPU完整验收。正常producer＋Mooncake＋LMCache＋MTP提前执行的全生命周期仍需单独功能证据；延通知机制诊断即便成功，也不并入这6次自然性能结果。

## 输出与MTP边界

- 六次均`output_lens=300`，全文字符串15对比较全部不同。温度0下差异保留为未解释事实；N16＋原MTP78非训练一致不是缓存一致性验收的替代，也不能据文本差异反推KV损坏。
- 六份benchmark只有`generated_texts`，没有output/sampled token IDs；`tokenizer_id`不是序列。现有proxy及P日志没有可比的实际first/output token ID字段，头若干token及P首token与D输出衔接均为**NOT_VERIFIED**，未从字符猜token。
- D0 draft/accepted token分别为原cold894/2、原warm891/3、原warm2 876/8，候选cold882/6、候选warm882/6、候选warm2 897/1。MTP3配置不代表明显接受收益；计数仅属减层诊断，不能推广完整模型表现或定位权重/KV故障。
